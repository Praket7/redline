# REDLINE — Stage 1 production foundation

A browser-based drone/hovercraft racing and combat game with four playable craft, two courses, cockpit/chase cameras, AI, ghosts and private multiplayer. The **source of truth** is this modular project, based on the frozen REDLINE v77 game.

## Quick start

```bash
npm install --ignore-scripts
python3 tools_restore_sources.py
python3 tools_restore_baseline.py
python3 build.py
python3 -m http.server 8080 --directory dist/site
```

Open `http://127.0.0.1:8080/`. Use the standalone file in `dist/REDLINE_v78_STAGE1_STANDALONE.html` to launch without a web server. When `three@0.128.0` is installed, **the Three.js engine is bundled locally in both builds**, avoiding the external CDN dependency.

This release keeps the original r128 renderer until a migration passes comparative WebGL tests. The [official Three.js migration guide](https://github.com/mrdoob/three.js/wiki/Migration-Guide) recommends stepwise changes. Do not upgrade to a new renderer solely to change the version number: REDLINE uses custom materials, shaders, photographic cockpit transparency and legacy color management.

## Tests

```bash
python3 tools_validate.py
python3 tests/test_stage1.py
node tests/test_stage1_runtime.js
for f in tests/legacy/*.js; do node "$f"; done
python3 tests/browser_ui.py
python3 tests/full_game_e2e.py
python3 tests/benchmark_sector.py
```

The `full_game_e2e.py` suite actually loads the Three.js world, launches **all four aircraft**, advances the 60 Hz simulation, checks WebGL render activity, and captures chase/FPV screenshots; it is not a mock. The benchmark captures Raven Slalom at a fixed camera with recorded frame metrics. GitHub Actions runs the suites with software WebGL. A failed or blocked browser test **must not be treated as a successful release**.

## Source layout

- `src/scripts/000_* ... 039_*` — original runtime scripts preserved in load order
- `src/data/` — deferred compressed aircraft GLB data scripts
- `src/styles/` — original CSS and the final FPV layout authority stylesheet
- `src/scripts/999_stage1_diagnostics.js` — F8 diagnostics
- `assets/images/` — 19 extracted cockpit assets
- `bundles/chunks/` — losslessly rebuilds large asset/source payloads via `tools_restore_sources.py`
- `bundles/late/` and `bundles/late_manifest.json` — checked-in hash-verified split archives restoring 28 missing original payloads
- `originals/v77_archive/` — compressed pieces of frozen source, verified and restored by SHA-256
- `tests/` — runtime, asset, regression, HUD and WebGL test suites
- `dist/` — **generated** outputs from `build.py`, not the source to edit
- `qa/` — reports and browser screenshots generated by tests
- `docs/` — migration and release gates

## Debugging

During a race press **F8** for FPS, p50/p95 frame times, draw calls, triangles, and update/render CPU measurements. `REDLINE_SIM_STATE()` publishes a read-only primitive snapshot from each 60 Hz tick. `REDLINE_CAPTURE_SHOWCASE()` captures a fixed camera at Raven Slalom without moving the player. `?redlineTest=1` exposes controlled browser hooks for real game tests.

## Release acceptance

A production-ready REDLINE release needs all source tests, actual WebGL startup/flight and capture tests, per-aircraft cockpit checks, no fatal browser exceptions, and performance measurements on real devices. See [Release Gates](docs/RELEASE_GATES.md). A green JavaScript syntax check alone is not sufficient.

## Technical constraints

The original v77 flight and AI behavior is intentionally preserved. Renderer modernization, deep simulation extraction, and deleting legacy CSS are gated on real browser regression results. They are not silently treated as complete if the corresponding tests cannot run. The source project supports a modernized renderer canary but does not force it on the playable build.

**CI-verified foundation:** [GitHub Actions run 45089329040](https://github.com/Praket7/redline/actions/runs/45089329040) passed asset restoration, unit and regression tests, responsive layouts, real WebGL hangar/flight/FPV checks for all four aircraft, live speed/altitude/boost instruments, and the Raven Slalom capture benchmark. Screenshots and logs are attached as the workflow artifact. The CI environment uses Chromium/SwiftShader; its ~10 FPS software-render result is **not** evidence of 60 FPS on target player hardware.

**Stage 1 is merged as a tested foundation, not fully closed as a production-quality renderer upgrade.** Remaining work is tracked in [renderer migration #2](https://github.com/Praket7/redline/issues/2), [simulation/render decoupling #3](https://github.com/Praket7/redline/issues/3), and [CSS consolidation + real-device QA #4](https://github.com/Praket7/redline/issues/4).
